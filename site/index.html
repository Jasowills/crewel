How it works

One terminal where you prompt the lead. The crew does the rest — isolated, live, review-gated.

Single-entry UX

crewel init once. Then crewel with no args prompts to init if missing, or launches the 6-pane UI with the lead focused. You type once; the lead fans out.

crewel init → crewel → prompt lead

◈

1 — Init

Pick team size, which agents and how many, and the orchestrator. Writes crewel.json + .crewel/teams/{name}/config.json.

⬢

2 — Launch

crewel spawns 6 real PTYs (ConPTY on Windows, forkpty on macOS) — lead 58% left, teammates 2+2+1 grid right. Each pane is interactive; you can chip in anywhere.

✦

3 — Prompt the lead

Lead decomposes your request into tickets with acceptance criteria, assigns round-robin, watches worktrees, handles needs-clarification, reviews, and is the only one who merges to main.

Works with your agents

Agent-agnostic — not locked to one vendor. Mix genuinely different types in one team.

OC

OpenCode

Primary daily driver. Highest reliability bar. First adapter built.

CC

Claude Code

Headless -p --output-format json + api_retry telemetry.

CX

Codex

exec --json with output-schema, sandboxed workspace writes.

MK

Mock

Deterministic dry-runs for CI and tests. No LLM required.

Add more via the AgentAdapter interface — one file per agent type. Core never talks to an agent directly.

Built for senior teams

Not a todo list — real tickets with status, assignee, dependencies, and acceptance criteria. Senior-bar by contract.

⬣

Isolated worktrees

Each teammate on crewel/{team}/integration + crewel/{team}/{id} branches. Main untouched until close-out PR.

◎

Live, not polled

fs.watch on messages/, tickets/, jason.log — every teammate and you are pushed the moment something relevant happens.

◐

Resilient

Interrupt, stall watchdog, rate-limit auto-pause, freeze after 3 failures, hybrid reassign only on clean worktrees. Worktrees never auto-deleted.

Ready to stitch your crew?
